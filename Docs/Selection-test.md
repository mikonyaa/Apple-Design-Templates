# Independent selection test

**Status: protocol prepared; no participant study has been conducted.** DOM checks can verify that all five links resolve, but cannot replace real readers.

Give a developer one task, a link to the English or Russian README, and no coaching about product names. Start at the top of the page. Ask which project they would choose and which limitation matters for their task. Record the answer before revealing the expected choice.

| Task | Expected project | Useful follow-up |
| --- | --- | --- |
| Improve tab navigation in an existing iOS app. | Liquid Glass Tab Bars | Is the standard TabView already sufficient? |
| Set up navigation for a new iPhone/iPad product. | Adaptive App Shell | Does the demo Create action persist a project? |
| Show brief status on Lock Screen/Dynamic Island. | Live Activity & Dynamic Island Kit | What must happen when changing an active scenario? |
| Build a focused Mac menu bar utility. | Mac Menu Bar Command Kit | Does Start Timer measure elapsed time? |
| Find non-adaptive Swift/UIKit assumptions before runtime QA. | ResizeLint | Can its Linux 1.0.0 binary run on bare Ubuntu? |

For each reader record: anonymous participant ID, task, language, viewport, chosen project, stated reason, limitation found, and observed navigation confusion. Timing is optional and must be measured if reported. Use local notes; the catalog does not need analytics.

A successful run means the reader chooses the expected project and can explain its relevant limit without assistance. Report the actual sample size and outcomes. Do not assign a score or claim usability success from the prepared protocol alone.
